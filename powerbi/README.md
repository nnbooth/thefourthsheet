# Financial statements in Power BI

A Power BI project (PBIP) for a **profit and loss, balance sheet and cash flow** that works for any organisation and any
chart of accounts. The files are plain text: a semantic model in TMDL and a report in PBIR. They're reviewed in git like code,
and they hold **no data**.

Everything here is generated by `tools/3_publish_site/powerbi_statements.py`. Don't edit the files by hand: change the
generator and run it again (or save from Power BI Desktop and copy the change back into the generator).

```
python3 tools/3_publish_site/powerbi_statements.py      # writes powerbi/ (also step 5 of build_site.py)
python3 tools/3_publish_site/tests/powerbi_check.py     # checks it without Power BI (also runs in GitHub Actions)
```

## How it works

The DAX never names a statement line. The layout is data, made in stage 1 by `tools/1_build_data/statement_lines.py`:

| Table | One row per | What it says |
|---|---|---|
| `statement_line` | line of each statement, in print order | the heading, account, subtotal or total; its `line_kind`; its `line_order` |
| `statement_line_account` | account in each line | which accounts make up the line, and the sign (`factor` +1 or -1) |

An account line is itself. "Total revenue" is the revenue accounts. "Gross profit" is every account above it (income +,
costs -). "Net assets" is the assets (+1) and the liabilities (-1). Stage 1 checks the layout before it writes it:

- every account with amounts is on exactly one line;
- every line of the locked August and September statements comes out to the dollar;
- every month's balance sheet balances, its cash flow ends on its cash, and its bottom line equals the ledger's profit.

If any check fails, the build stops.

One measure, **`[Amount]`**, works out every line for the period in context:

| `line_kind` | Amount |
|---|---|
| `heading` | 0, shown blank (so the row prints) |
| `value`, `sum` on the P&L | the line's accounts in `GL` (daily postings) over the period |
| `value`, `sum` on the balance sheet | the line's accounts in `Balance` at the period's last day |
| `value`, `sum` on the cash flow | the line's accounts in `Cash flow` over the period |
| `opening_cash` / `closing_cash` | cash at bank at the end of the day before the period / at the period's last day |

The **Period view** calculation group turns `[Amount]` into the columns: This month, Last month, Change on last month,
% change on last month, Same month last year, Change on last year, % change on last year, Year to date, Last year to date,
Change on last year to date, At 30 June, and Change since 30 June. The financial year runs from July to June. Each page
filters the group to the columns it needs. A balance needs no special handling: "Year to date" on a balance-sheet line is
the balance at the period's end, which is right.

Every amount is blank unless exactly **one organisation** is selected, so no total ever adds two businesses together.

## The model

| Table | From | Notes |
|---|---|---|
| Date | `dim_date` | Marked as the date table (`calendar_date`). Month slicer on `month_name`. |
| Organisation | `dim_org` | Only the organisations that have statements. |
| Account | `dim_account` | The chart of accounts. |
| Statement line | `statement_line` | Holds the measures. `row_label` goes on a matrix's rows. |
| Statement line account | `statement_line_account` | Hidden. Read only by `[Amount]` (through `TREATAS`, with no relationship to Account). |
| GL / Balance / Cash flow | `fact_gl_daily`, `fact_balance_month`, `fact_cash_flow_month` | Hidden facts. Month-end tables are dated on the month's last day. |
| Period view | calculation group | The columns. |

`row_label` indents detail lines with an em space. It also adds invisible zero-width spaces, so a label two organisations share
(for example "Cash at bank") can still sort by each organisation's own `line_order`.

**Checks** page: `[Balance sheet check]`, `[Cash flow check]` and `[Profit check]` for every month. Each should show `-`
(zero). If one doesn't, the layout is missing an account.

## Opening it

1. Install Power BI Desktop (Windows) and switch on *File > Options > Preview features > Power BI Project (.pbip) save option*
   and *Store semantic model using TMDL format*. Recent versions have both on.
2. Open `powerbi/Financial statements.pbip`.
3. Go to *Transform data > Edit parameters*:
   - **DataSource** `CSV`, with **DataFolder** set to this machine's OneDrive `...\Projects\The Fourth Sheet\Data` folder, or
   - **DataSource** `Azure SQL`. Sign in with your Microsoft account. **SqlServer** and **SqlDatabase** are already filled in.
4. Refresh. Pick an organisation. The pages open on the most recent locked month.
5. Compare the pages with **`Data documentation/Power BI/Financial statements - expected numbers.md`** in OneDrive. The generator
   writes it from the CSVs, using the same rules as the DAX. Every number should match.

Power BI Desktop writes `.pbi/localSettings.json` and `.pbi/cache.abf` next to the model. They're per-machine files and are git-ignored.

**Not yet opened in Power BI Desktop.** The report files pass Microsoft's published JSON schemas. Every field and DAX reference
is checked against the model. Every number the DAX must produce is checked in stage 1. But TMDL parsing and DAX evaluation
need Power BI itself, so the first open is the real test. If Desktop rejects something, fix it in the generator, not in the
files. The likely spots are the custom theme (the report sets no base theme) and the measure's dynamic format string.

## Using it for a client

The model only needs its eight source tables, with the same columns:

1. **Chart of accounts** (`dim_account`): one row per account and per subtotal, with `statement`, `section`, `line`,
   `line_level` (`detail`, `subtotal`, `total`, `key`) and `line_order`.
2. **Facts**: daily postings (or monthly ones, dated on the month's last day) for the P&L, month-end balances, and monthly
   cash flows. Income is +, costs are -. Assets, liabilities and equity are all +.
3. **The layout**: run `statement_lines.build()` on the client's accounts. Or write `statement_line` and
   `statement_line_account` by hand: they're small, and they're exactly what the client's management pack prints. If the
   client's statement has a subtotal the rules don't know, the build stops and names it. Add a rule to `rollup()`.

No measure changes. A different layout, such as gross margin by division or a budget column, is a new row in
`statement_line`, not new DAX.

**Adding a budget**: load a budget fact at the same grain as GL. Add a `[Budget]` measure built like `[Amount]`'s P&L branch
(same `TREATAS` over the line's accounts), and put it in the matrix values next to `[Amount]`. The Period view then gives it
the same columns: budget this month, year to date, and so on.

**Adding a page**: add it to `PAGES` in the generator, with its statement and Period view columns.
